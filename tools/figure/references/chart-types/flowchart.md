# 建模流程图规范

方法/结构示意，不是数据图。与三类候选图（原始数据图 / 过程图 / 结果图）**并列但不占用其配额**。

## 适用与边界

- 回答"模型怎么组织和求解"，而不是"数据长什么样"。
- 与数据证据图区分用途；流程图不能代替支撑结论的数值表或结果图。不设置统一图数配额。
- 节点与连线必须来自**已确认的模型与真实代码**；不得画没有依据的模块、分支或数据流。

## 何时画

- 当总体依赖关系有助于理解时，生成覆盖输入、子问题依赖、模型、求解、验证与输出的流程图；简单任务可用文字说明。用户或适用比赛规则另有要求时，记录其来源后执行。
- 仅当某个子问题存在**独立分支、循环或三步以上求解链**时，才为该子问题增加一幅子问题流程图。
- 不为凑数量重复绘制共享流程；同一流程只画一次。

## 样式规范

- 黑白或低饱和单色为主；不使用装饰性渐变、阴影或立体效果。
- 节点形状按语义固定：

  | 形状 | 语义 |
  |---|---|
  | 圆角矩形 | 起止（输入 / 输出） |
  | 矩形 | 处理、计算、建模 |
  | 菱形 | 判断、分支条件 |
  | 平行四边形 | 数据或文件读写 |

- 箭头为**实线有向**，表示控制流或数据流；尽量不交叉连线，必要时重排节点或分层。
- 节点标签简短（建议 ≤ 12 字），术语与正文、`术语表格.md` 一致。
- 编号使用 `图N`，与论文其他图**共用连续编号**；题注写在图下方，并在正文至少引用一次。
- 需要区分阶段时用浅色底纹分区，但必须保证**灰度下仍可辨**。

## 生成路线

1. 优先复用项目已有的流程图生成器（若 `PROJECT_ROOT` 内已存在）。
2. 项目选择 `graphicsTools.drawio=true` 时加载 `tools/figure/integrations/drawio/SKILL.md` 并保留可编辑 `.drawio`。没有选择时，用已安装的 **Matplotlib 或 MATLAB 原生绘图能力**（`patches` / `annotation` / `arrow` 等）。**不为流程图新增依赖**；不要求安装 Graphviz、Mermaid 等外部渲染器。
3. **不把** PowerPoint 截图、手工修改的位图或 AI 生成的概念图作为权威源——它们无法与代码逐句对应，也无法复现。
4. 保留可运行的生成代码，使流程图与模型、代码同步演进。

## 文件与导出

- 命名：`flow_overall_model.*`（总体）或 `flow_qN_model.*`（子问题）。
- 输出：**SVG**（可编辑矢量）＋ **至少 300 DPI PNG**，条件允许再输出灰度预览。
- 按项目模板要求选择导出格式，不设通用 SVG/PNG 配对门槛；drawio 路线保留原生 `.drawio`。对已导出的 SVG 检查可编辑文本，对印刷 PNG 检查实际尺寸和 DPI。
- 在论文最终尺寸下检查：字体、箭头、对齐、裁切、灰度辨识。

## 自检清单

- [ ] 每个节点与连线都能对应到真实模型或代码，没有凭空出现的模块。
- [ ] 每个子问题都被总体图或某幅子问题图覆盖。
- [ ] 未替代结果图；未计入三类候选图配额。
- [ ] SVG 文本可编辑、PNG ≥ 300 DPI、灰度下结构可辨。
- [ ] 有连续编号、题注和正文引用，没有孤儿图。
- [ ] 生成代码保留且可重跑，重跑结果与论文用图一致。
