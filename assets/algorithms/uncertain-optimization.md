# 不确定性条件下的优化

**何时加载**：需求、价格、供应、天气等不确定量会改变方案可行性或成本。先说明信息何时揭示，再让不确定性进入决策；求出确定性最优解后扰动几次只是敏感性分析。每道子问题最多两个独立模型体系；同一随机/鲁棒模型的场景数、风险参数或求解器变化不自动新增模型。

## 选择路线

| 证据与目标 | 路线 | 不可省略 |
|---|---|---|
| 只有少量可解释情景 | 情景分析/情景约束 | 来源、权重是否有概率含义、覆盖边界；不能凭空声称置信水平 |
| 概率/样本有依据，允许事后补救 | 两阶段随机规划 | 共同先验决策、情景补救、期望/风险成本、非预见性 |
| 多次观察后依次行动 | 多阶段随机规划/场景树 | 节点信息集、条件概率、同历史共享动作、跨期状态 |
| 只有可信区间/不确定集 | 鲁棒优化 | 集合来源、最坏情形、保守性、是否允许可调补救 |
| 允许小概率违约或重视尾部损失 | 机会约束、CVaR 等 | 分布/采样假设、水平的题目依据、样本外违约及尾部稳定性 |

概率与不确定集需要数据、领域证据或明确的假设来源；估计场景、选风险参数和最终评估应划分数据，时间数据保留顺序。不把“考虑了三个场景”写成“已经覆盖所有风险”。

## 两阶段与非预见性

一般形式为

$$\min_{x\in X}\ c^Tx+\sum_s p_sQ(x,\xi_s),\qquad Q(x,\xi_s)=\min_{y_s}\{q_s^Ty_s:W_sy_s=h_s-T_sx,\ y_s\in Y_s\}.$$

$x$ 在场景揭示前选，所有场景共享；$y_s$ 揭示后才选。若使用各场景复制的 $x_s$，必须加入相等约束。去掉这些约束得到的是先知信息解，不能当可实施策略。检查补救是否总可行，不可行场景不能删除后重新归一化掩盖问题。

多阶段时同一树节点/相同已观测历史的动作相同，离开该节点后才可分支。路径概率是沿途条件概率乘积；独立边际抽样会破坏真实时间相关性。场景树增长快，需要说明采样/缩减误差与计算预算。[mpi-sppy 官方文档](https://mpi-sppy.readthedocs.io/en/latest/) 支持场景离散的随机规划；[scenario_creator 合同](https://mpi-sppy.readthedocs.io/en/latest/scenario_creator.html) 说明节点及非预见变量的组织方式。

小规模先解确定性等价式并验证，大规模再按结构考虑分解。mpi-sppy 的 Pyomo/MPI/外部求解器是可选扩展，本卡的 SciPy 示例并未调用或实现多阶段分解。[官方实例入口](https://mpi-sppy.readthedocs.io/en/latest/examples.html)

## 鲁棒对偶与边界

静态鲁棒约束是 $a(\xi)^Tx\le b$ 对所有 $\xi\in\mathcal U$ 成立。若各系数独立满足 $a_i\in[\bar a_i-r_i,\bar a_i+r_i]$，则最坏消耗为 $\bar a^Tx+\sum_i r_i|x_i|$；**只有明确 $x\ge0$ 时**才能化为 $(\bar a+r)^Tx\le b$。相关不确定性、多面体/椭球集和可调决策需要对应推导，不能无条件套上端点。

鲁棒可行只相对于所选集合；集合太小可能漏风险，太大会过度保守。优化均值、最坏值和 CVaR 回答不同问题，比较时统一成本单位、可行域、信息结构和预算，不能仅比较不同目标函数的数值大小。

## 可运行例与验证

[uncertain-optimization.py](uncertain-optimization.py) 不读取真实市场数据：

- 两阶段库存：需求 1/3 各概率 0.5，预先采购单价 2，余货成本 1、缺货成本 7、容量 10。LP 使用一个共同采购量，补救满足 $x-h_s+z_s=d_s$。解析最优 $x=3$、期望成本 7；逐段线性成本枚举断点独立验证。
- 按平均需求先选 $x=2$ 再放回原场景评估，成本为 8；可提前知道需求分别订货的平均成本为 4。最小化问题满足先知下界 $4\le7\le8$，本例 VSS=1、EVPI=3；不能把先知 4 作为可部署成绩。
- 鲁棒资源：利润 $(3,2)$，系数中心 $(1,1)$、半径 $(0.5,0.2)$、容量 3、决策非负。最优 $(2,0)$、利润 6；测试枚举不确定盒四个顶点检查可行性。

```powershell
python assets/algorithms/uncertain-optimization.py
python -m unittest discover -s tests -p test_algorithm_modules.py -v
```

只需 NumPy/SciPy，不需 MPI、商业求解器或付费 API。真实任务保存场景/权重/种子/代码哈希、非预见性定义、求解状态与界、场景约束残差，再做独立样本外成本、违约率和风险区间评估。求解这个小例不能证明真实需求分布、场景数量或鲁棒集合正确。
