# 论文手工作流程

> 共享运行时、当前 profile、用户要求和已核验规则优先；以下高级工具步骤仅在依赖/授权具备且任务需要时加载。缺能力时保留可验证产物并报告审查等级，数量建议不阻断。
## 一、锁定官方规则

生成前确认目标竞赛、届次、语言、提交格式和官方规则来源。优先使用用户提供或从官方网站取得的当届官方 Word/LaTeX 模板、摘要页、编号页和格式说明。默认 Word；按用户选择生成仅 Word、仅 LaTeX/PDF 或两种格式。当届官方提交要求仍决定实际可提交的版本。把规则来源与届次记录在内部检查中，不把往届经验写成固定规则。

## 二、检查输入

必须具备：

- 题目及附件
- `题目分析报告.md`
- `术语表格.md`
- 可运行代码
- 实际运行结果表格
- 支撑核心主张所需的图或表，类别与数量按任务确定
- 方法需要或官方/用户要求时的建模流程图（`flow_overall_model.*` / `flow_qN_model.*`）
- 已核验的文献元数据

关键输入缺失时回退到对应角色补齐，不能推测数值、伪造图表或编造引用。

## 三、内部论证映射

写作前通过共享运行时 claim-add 持久化主张—证据映射：每个结论对应公式、表格、图、代码输出或文献。映射保存在 .math-modeling/ 内部元数据中，供恢复和审计，不写入论文正文。

篇幅、公式、图表数量由任务和带来源的规则决定；历史工具的字数/页数默认值不是通用门槛。先用共享 validate，再按当前 profile 显式配置高级检查。官方页数上限必须核验当届来源，不能由本文历史记录推定。

## 四、W1 证据大纲

在长篇正文和双格式排版前，为每个子问题列出拟写核心主张及其公式、结果表行列、图文件、代码输出或已核验 DOI，由独立质检 Subagent 检查：

- 每个必须回答的结论类型都有精确证据路径。
- 摘要拟用关键数值与实际结果一致。
- 公式、图表和引用都有章节落点；需要的建模流程图已规划入文章节与引用。
- Word 与 LaTeX 共用同一份正文和证据源。
- 符号说明表只取自 `术语表格.md` 的“符号、含义、单位”三列，并已确定数学排版方式。
- 如需附录，已记录每个附录的必要性、主题、正文引用点、内容、当届页数口径，以及是否要求完整代码和对应源码清单。

存在核心证据缺口时返回建模手或编程手补齐；严格模式下 `W1` 未返回 `PASS` 不开始正文。证据大纲保存在共享项目内部元数据，不写入论文。

## 五、截止时间与可提交版本保护

真实竞赛或其他有明确截止时间的任务，按 `../../../../references/交付与截止时间协议.md` 读取当前系统时间并核验当届官方截止时间、时区和提交限制。在长篇排版前用最小真实样例走通代码、图表、DOCX/PDF、支撑材料和压缩包链路，把转换、渲染、人工检查、压缩和上传视为正式任务。

首次得到完整且满足已知硬约束的论文和支撑材料时保存 Checkpoint V1，后续优化在副本或新版本上进行；V1 不得被原地覆盖。安全时间允许时形成 Checkpoint V2，随后内容冻结、最终导出并完成完整性与合规检查。临近最迟安全导出时间时，若新修改失败后无法回退并按时提交，默认不执行该修改。

## 六、构建论文

先锁定共同的正文、数据、图表、公式和参考文献，再生成用户选择的格式；不得分别改写导致结论或数值不一致。

### 符号说明表

- 固定只使用“符号、含义、单位”三列，内容来自建模手的 `术语表格.md`，不在写作阶段另建第二份符号定义。
- 符号必须以真正的数学格式呈现：Word 使用原生 OMML，LaTeX 使用数学模式；上下标、希腊字母、粗体向量和矩阵按数学字形排版，最终渲染不得露出 `x_ij`、`alpha`、下划线、反斜杠或公式定界符。

### 附录

- 先核验当届官方规则是否允许或要求附录、是否计入页数以及代码、数据、AI 使用说明和匿名要求；未知时明确标记，不用往届规则替代。
- 正文保留回答题目所需的模型、关键公式、结果和验证，不能把核心论证全部移入附录。附录只放过长推导、补充参数表、扩展验证、伪代码或官方明确要求的内容。
- 每个附录只承担一个主题，并与正文双向引用。官方模板未规定时，按“附录A、附录B”组织，编号使用“式(A.1)、图A.1、表A.1、算法A.1”并在各附录内连续。
- 当届官方规则或用户明确要求附完整代码时，必须把与最终结果一致的真实、完整源码写入附录；禁止用一段说明文字、伪代码、截图、“代码见附件”、省略号、`pass`、待实现占位注释或缺失的函数代替。多文件项目至少包含可运行入口及其全部项目内依赖。
- 附录代码从实际通过运行的权威源码生成或逐文件核对，不手工重写；在 `W2` 前复核文件清单、关键参数、随机种子和输入方式，并执行相同源码确认仍能产生论文采用结果。官方和用户均未要求论文附完整代码时，完整可运行源码进入支撑材料。

### Word 分支

1. 从当届官方参考模板创建文档；模板正文示例必须清除，但保留样式、分节、页眉页脚和页面设置。
2. 使用 `../../../../tools/docx/scripts/paper_format.py` 添加标题、段落、公式、表和图片。
3. LaTeX 只作为公式输入，转换成 Word 原生 OMML；不支持的命令必须报错。
4. 表格使用可编辑 Word 表格；图使用编程手实际生成的文件，总体建模流程图使用编程手产出的 `flow_*` 文件。
5. 每幅图和每个表均设置连续编号与题注，并在正文中至少引用一次；文献编号、正文引用和 DOI 双向核对。

已有完整 LaTeX 主稿且需要同时交付两种格式时，可调用 `docx(action="convert_latex")` 或 `equations.py convert-latex` 生成 Word 初稿，以减少正文漂移；随后仍须按官方 DOCX 模板检查样式、分页、浮动体、交叉引用和参考文献。

### LaTeX 分支

1. 先运行 `latex_paper.py doctor` 检查官方模板需要的引擎、参考文献后端、PDF 审计工具和 Pandoc（需要 Word 时）。
2. 用 `latex_paper.py init` 把当届官方 LaTeX 模板整个目录复制到 `PROJECT_ROOT/完整论文-LaTeX/`；保留 `.cls`、`.sty`、`.bst`、字体和模板图片，并记录模板 URL、届次、哈希及嵌套主入口。没有官方模板时才使用内置构建基线。
3. 在复制件中填充正文、公式和已核验的 BibTeX 条目，不修改原始模板或 `SKILL_ROOT`。把 `PROJECT_ROOT` 权威代码和图表复制到 LaTeX 项目后，立即用 `latex_paper.py bind` 建立资源哈希绑定；必要结果图用标签 `fig:qN-` 关联子问题；无图的结论通过表格、公式或运行证据支撑。
4. 按官方模板要求选择 XeLaTeX、LuaLaTeX 或 pdfLaTeX，优先由可实际执行的 `latexmk` 编译；不可执行且无外部文献时回退为两次所选引擎编译。不启用 shell escape，不自动安装宏包，不在失败后擅自换引擎。
5. 消除编译错误、未解析交叉引用和未解析文献；每个图表都有题注、真实内容与 `label`，并由图表环境外的正文 `ref`。同时检查权威资源—源码—PDF 哈希、PDF 总页数、正文页数、附录边界、空白页、页面尺寸、字体嵌入和图片 DPI。

## 七、验证

Word：

```powershell
python "<SKILL_ROOT>/tools/docx/scripts/self_check.py"
python "<SKILL_ROOT>/tools/docx/scripts/office/validate.py" "<PROJECT_ROOT>/完整论文.docx"
python "<SKILL_ROOT>/tools/docx/scripts/equations.py" verify-conversion "<PROJECT_ROOT>/完整论文.docx"
```

最后一条仅适用于 LaTeX/Markdown 经 Pandoc 转换得到的 DOCX。另需调用 `paper_format.validate_paper_structure()` 检查篇幅、公式/图/表数量、图表正文引用与参考文献对应关系，并把渲染后的实际页数传入 `rendered_pages`。随后抽检分页、符号数学排版、公式、附录、页眉页脚和目录，并从实际 DOCX 提取文本，检查 `**`、反引号、标题 `#`、表格竖线、公式定界符 `$`/`$$`、行首列表标记和 `[待补充]` 等 Markdown 格式残留或占位符。命中项须逐条人工判断；非正文所需的残留必须从源文件清除、重新导出并复验。任何错误或无合理覆盖依据的预警都应修复后重新生成。

LaTeX：

```powershell
python "<SKILL_ROOT>/tools/latex/scripts/latex_paper.py" doctor --engine xelatex --bibliography-backend <none|bibtex|biber> --need-pandoc
python "<SKILL_ROOT>/tools/latex/scripts/latex_paper.py" build "<PROJECT_ROOT>/完整论文-LaTeX/main.tex" --engine xelatex --publish "<PROJECT_ROOT>/完整论文.pdf"
python "<SKILL_ROOT>/tools/latex/scripts/latex_paper.py" validate "<PROJECT_ROOT>/完整论文-LaTeX/main.tex" --pdf "<PROJECT_ROOT>/完整论文.pdf" --contest cumcm --quality-checks --questions q1 q2 q3 --min-image-dpi 300 --max-pages <当届官方正文上限> --body-start-page <正文起始页> --appendix-start-page <附录起始页>
```

没有附录时省略 `--appendix-start-page`。构建与转换警告默认阻断发布；只有逐项核对后才能用精确允许正则和具体覆盖理由继续。项目 profile 的建议目标不阻断交付；只有带来源的官方/用户硬约束必须满足。自动校验通过后，再打开实际编译 PDF，抽检摘要页、正文和附录边界、分页、公式、图表、页眉页脚、字体和参考文献。

## 八、W2 论文终检

用户要求的全部格式冻结且各自确定性门禁全部返回 0 后，按 `../../../../references/Subagent调度.md` 派发独立质检 Subagent。质检者核对当届规则、主张—证据、数值与单位、符号数学排版、附录边界与双向引用、要求附完整代码时的源码完整性和可运行性、需要的建模流程图已入文且与真实模型一致、图表编号和正文引用、Markdown 格式残留、支撑材料完整性及实际渲染效果；同时生成两种格式时再检查 Word/LaTeX 一致性。失败回执必须定位到页码、章节、命令或来源，并按根因返回对应角色；独立验收未通过时只能明确受限交付，不能声称完整通过。

## 九、交付

按用户所选 paper_format 交付 Word、LaTeX/PDF 或两者；保留对应真实构建清单。内部映射与日志保存在 .math-modeling/，不混入论文。最终包核对命名、格式、大小和目录结构，并实际解压或打开；未经用户或平台证据确认不声称已提交。
