# 数学建模

先理解题目，再生成模型、实际运行求解，最后基于证据写作。用户要求优先；竞赛格式以当届官方规则为准。交付物使用边界见 `使用指南.md`，论文需由用户理解与复核。

## 开始与路径

- `SKILL_ROOT` 是本文件目录，只读；`PROJECT_ROOT` 是独立题目目录，输入附件只读，输出写入项目目录。
- 首次更新说明任务范围、两个根目录、已知规则和能力缺口；只读取当前阶段需要的入口。
- 读取 `references/共享运行时.md`，用共享 CLI 初始化/恢复项目并运行 `doctor`。选择 `balanced`、`short` 或 `competition` profile 和用户需要的格式；默认 `balanced`、Word。
- profile 的建议图数、篇幅和模型数量不是通用硬门槛。官方规则和用户明确要求写入带来源的项目 rules；不凑图、凑字数、凑模型。
- 无 CLI 时可按知识流程产出结果，报告未记录/未验证状态；无独立审查能力时按审查协议受限交付，不声称独立通过。

## 路由与产物

| 意图 | 当前入口 | 产物与前置条件 |
|---|---|---|
| 分析、选择模型 | `references/roles/建模手/SKILL.md` | `题目分析报告.md`、`术语表格.md`；模型合同写入报告 |
| 求解、代码、图表 | `references/roles/编程手/SKILL.md` | 可运行代码、真实结果、必要图表、`results/复现清单.json`；需可执行模型说明 |
| 写作、修改论文 | `references/roles/论文手/SKILL.md` | 用户选定的 Word、LaTeX/PDF 或两者；需真实结果与可追溯证据 |
| 完整任务 | 按上述顺序加载 | 不预读全部知识库；缺证据时回到对应阶段 |

不在单阶段任务中强制完成其他阶段。每个核心结论必须有结果表、公式推导、图或来源支撑；图表是否必要由证据用途决定。多步骤/分支模型宜绘流程图；官方或用户要求时必须提供。

## 阶段与证据

共享运行时持久化阶段、运行记录、产物、主张和审查回执。主 Agent 写权威产物；Subagent、外部独立 Agent 或人工审查的来源等级必须明确，作者自检不能冒充独立审查。

- `M1`：模型可实现性；`P1`：最小真实求解链；`P2`：结果与复现；`W1`：主张—证据大纲；`W2`：最终论文与实际渲染。
- 禁止等全流程结束后才首次审查。严格模式按前置关系推进：P1 在全量实验前，P2 在论文规划前，W1 在长篇正文前。
- 默认只安排独立质检；额外协作遵循用户和宿主授权，不为每个图/函数重复派发。协议见 `references/Subagent调度.md`。
- 用 `run` 记录真实命令和退出码，`artifact-add` 关联产物，`claim-add` 保存主张证据。产物修改后旧回执失效；不能口头覆盖失败。
- 缺依赖、格式引擎或审查能力时保留可验证部分，报告剩余工作。确定性校验和独立审查分开记录。

## 按需加载

| 情形 | 入口 |
|---|---|
| 选算法、基线与验证 | `references/算法索引.md`，再读具体算法卡片 |
| 论文检索 | `tools/paper_search/SKILL.md`；来源匹配不代表原文支持结论 |
| 数据图与流程图 | `tools/figure/SKILL.md` |
| PDF、Excel | `tools/pdf/SKILL.md`、`tools/xlsx/SKILL.md`，先检查扩展依赖与组件授权 |
| 高级 Word / LaTeX | `tools/docx/SKILL.md`、`tools/latex/SKILL.md`，按所选格式加载 |
| 截止时间与打包 | `references/交付与截止时间协议.md` |

基线优先：先跑简单可靠的方法，再用验证证明复杂方法增益。模型数量、异常阈值、容差、边界预期和退化策略由问题合同决定，不套通用数值。

## 完成与反馈

运行 `validate` 和 `complete`，检查当前项目真实状态；未通过的检查不得报告通过。最终说明交付路径、真实运行结果、核心数值、审查等级、未解决问题及验证边界。仅生成文件、脚本退出零或两来源匹配都不等于科学结论正确。竞赛任务保存可交付快照；未经用户或平台证据确认，不声称已提交。
