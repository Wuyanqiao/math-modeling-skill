# 使用指南

本项目辅助理解问题、建立模型、执行求解和整理论文。用户决定任务范围、模型目标和输出格式；竞赛条件以当届官方规则为准。软件记录的 PASS 有明确检查范围，不代表结论天然正确或主办方已接受提交。

## 选择任务

- 完整流程：在独立题目目录加载根 SKILL.md，按建模、编程、论文推进。
- 单阶段：scope=modeling、programming 或 paper，不强制补跑其他阶段。
- 小型任务：short profile，按结论所需证据组织内容。
- 竞赛任务：competition profile，将核实后的约束写入带来源的 rules，不把历史默认页数当作官方规则。
- DSH 与其他宿主：共用 CLI 和项目状态；具体宿主权限和安装方式遵循适配文档。

## 项目文件

SKILL_ROOT 放软件、知识和模板；独立 PROJECT_ROOT 放输入、代码和交付物。输入附件保持只读，运行声明的文件会复制到独立执行目录。

| 文件 | 用途 |
|---|---|
| 题目分析报告.md、术语表格.md | 模型假设、约束、符号与验证合同 |
| data/、inputs/ | 原始输入 |
| 代码、results/、figures/ | 实现、数值与必要图表 |
| results/复现清单.json | 哈希、参数、种子声明、环境与命令 |
| 完整论文.docx / 完整论文.pdf / LaTeX 源码 | 用户选择的论文格式 |
| .math-modeling/ | 状态、日志、审核、证据与恢复版本，不混入论文正文 |

命令见 [共享运行时](references/共享运行时.md) 与 [接口契约](RUNTIME_API.md)。软件不会自行上传或提交比赛作品。

## 判断是否可用

核对模型是否回答题目、约束与单位是否一致、代码是否实际执行、论文数值能否定位到结果、图表和引用是否支持结论。结构校验不能代替视觉检查与科学审查。

作者自检、独立 Agent、人工审核分别记录真实来源、身份和范围。缺少独立审查时保留已有成果并明确剩余工作，不伪造 PASS。两个检索来源收录同一论文只代表元数据匹配，不代表已读原文。

提交前保存可恢复快照，再按当届规则核对格式、材料和 AI 使用披露。恢复先返回文件影响预览，只有携带匹配版本的明确 apply 请求才修改文件，并先保存恢复前版本。

外部工具依赖与继承组件授权见 [安装说明](docs/installation.md) 和 [第三方说明](THIRD_PARTY_NOTICES.md)。
