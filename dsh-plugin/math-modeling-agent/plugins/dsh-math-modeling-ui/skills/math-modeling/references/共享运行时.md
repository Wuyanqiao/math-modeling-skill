# 共享运行时与宿主能力

通用 Skill、命令行和 DSH `mm_*` 共用 `.math-modeling/` 项目状态。知识入口不绑定特定 Agent；状态、证据和校验由 `<SKILL_ROOT>/scripts/mathmodel.py` 处理。所有命令从题目目录执行，脚本使用绝对路径，参数遵守宿主 shell 的转义规则。

```powershell
python "<SKILL_ROOT>/scripts/mathmodel.py" init --project-root "<PROJECT_ROOT>" --options '{"scope":"full","profile":"balanced","paper_format":"word"}'
python "<SKILL_ROOT>/scripts/mathmodel.py" doctor --project-root "<PROJECT_ROOT>"
python "<SKILL_ROOT>/scripts/mathmodel.py" state --project-root "<PROJECT_ROOT>"
```

自动适配器可使用 `--request-base64` 传输 JSON 请求，避免将用户输入拼入 shell。具体字段以根目录 `RUNTIME_API.md`、CLI 帮助及 `mathmodel_runtime/resources/schemas/` 为准；不要猜测字段或自行改写状态文件。

## 生命周期

1. `init` 创建项目；已有项目先 `state`，不要重新初始化丢失历史。
2. `doctor` 发现当前能力；只准备当前任务必需依赖。
3. `phase` 进入当前阶段；`todo` 维护任务范围与阻塞。
4. `run` 记录真实命令、输入和代码哈希、参数、种子、输出与退出码；命令必须从项目目录可复现。
5. `artifact-add` 登记结果、图、代码、报告等，关联运行与所属问题；`claim-add` 将核心主张绑定证据位置。
6. `gate-prepare` 生成 task_id 和快照；独立审查后 `gate-record` 保存原回执。需要真实 reviewer_id 和文件哈希证据，不能虚构身份制造独立性。
7. `validate` 检查任务产物和硬约束；`complete` 汇总状态。产物变化后重新检查受影响部分。
8. `checkpoint-create` 保存版本，`checkpoint-list` 列出，`checkpoint-restore` 恢复；恢复前查看影响，保护用户新输入。

## 能力与审查等级

作者自检、宿主 Subagent、外部独立 Agent 与人工审查必须标明真实来源、身份、范围和输入快照。无 Subagent 时继续可验证计算，报告“产物已生成，独立验收未完成”，或接入真实外部审查；不能伪造 PASS。

`balanced`、`short`、`competition` 均不自动把历史图数/字数/页数变成官方要求；只有带规则来源的项目 rules 才增加硬约束。严格独立审查与能力限制由项目配置和回执明确表示。

缺网络、搜索源或格式引擎仅阻塞对应能力；记录 failed/empty/unavailable，保留已有可靠结果。替代工具需要满足用户需求并如实报告验证差异。

## 格式扩展

基础校验检查文件结构、非空内容、运行记录、哈希和证据引用，不替代视觉/科学审查。高级 DOCX、LaTeX、PDF、XLSX 工具另行准备依赖并核对各组件 LICENSE。未打包扩展时用 doctor 报告，不能根据一份 SKILL.md 推断脚本已安装。

内部证据持久化用于恢复和审计，不写入正式论文。建议数量只作提示，不用重复图或空内容满足配额。

LaTeX 交付需登记 `.tex` 入口，并用直接 TeX 工具的 paper run 关联代码和 PDF；运行记录保存实际 argv 与执行器路径。自定义包装脚本不自动获得编译来源信任。Word 的 max_pages 检查要求当前 DOCX 是渲染运行的输入，且对应 PDF 输出已登记；仅有一个短 PDF 不能证明 Word 页数合规。
