# Subagent 调度与阶段门禁

主 Agent 写入权威产物，质检者默认只读且未参与被审产物编写。作者自检、脚本校验与独立验收分别记录；不存在用声明身份自动证明独立性的机制。用户与宿主授权优先，默认只启用必要质检，可选协作默认关闭；只有用户明确启用或既有授权覆盖时增加调研/实验协作。

## 生命周期

先读 `共享运行时.md`。使用共享 CLI `gate-prepare` 获取 task_id、snapshot_hash 和审查范围，实际派发给宿主 Subagent、外部独立 Agent 或人工审查者；运行时本身不调度 Agent。不要给出期望 PASS 或作者已正确的暗示。

审查者读取题目、当前验收条款、真实文件、命令日志及必要上次回执；不传无关历史。模型、输入、代码、产物发生实质变化时旧回执失效，修正后重新准备快照并复验。禁止等全流程结束后才首次审查。

| 门禁 | 时机 | 证据 |
|---|---|---|
| M1 | 模型报告作者自检后 | 子问题覆盖、假设、公式/单位、约束、实现和验证合同 |
| P1 | 最小求解链跑通、全量实验前 | 原始输入或等价小实例、命令、退出码、数值、可行性与容差 |
| P2 | 代码与必要结果/图冻结 | 真实复现、代码/输入/输出哈希、环境、参数、图表语义、基线对照 |
| W1 | 长篇正文前 | 逐个主张对应的表行列、公式、图、运行结果或原文位置 |
| W2 | 用户要求的格式冻结后 | 主张/数值、规则、引用、实际渲染、Markdown 格式残留、支撑材料完整性；同时生成两种格式时再检查 Word/LaTeX 一致性 |

单阶段仅执行该范围门禁。P1 不要求最终性能和完整图集；图数、篇幅不作为通用门槛。严格模式须通过相应前置，正常受限交付必须如实标明独立验收未完成。

## 机器回执

`gate-record` 接收的 receipt（字段详见根目录 `RUNTIME_API.md`）：

- `task_id`、`snapshot_hash`：来自当前 gate-prepare；必须对应输入快照。
- `reviewer_id`：真实审查身份，不同于作者；`review_source` 为 subagent / external / human。
- `status`：PASS / FAIL / BLOCKED；`scope` 说明覆盖与未覆盖内容。
- `evidence`：真实 `{path, sha256, locator?}`；页码、命令、退出码、数值或来源可放定位说明。
- `findings`：`{level: P0/P1/P2, text}`；P0/P1 未解决不可 PASS。
- `rework`：修正角色、必要修改与复验入口。

缺依赖、权限、输入或可验证证据返回 BLOCKED；主 Agent 不得口头覆盖 FAIL。没有 Subagent 时仍可执行确定性检查并受限交付，或接受真实人工/外部独立审查；不能把作者自检伪装为独立通过。身份记录是审计声明，除非宿主另外证明，不声称实现身份认证。

## 可选协作与并行边界

- 官方规则核验、附件盘点、文献与模型族调研：返回来源、哈希、未知项与建议；不要按搜索引擎拆分调研。
- 隔离算法原型、独立实验批次、Python/MATLAB 对照实现：在独立目录执行，共用模型合同，返回真实命令/环境/结果，不修改权威文件。
- 术语核验：返回术语、单位、来源和位置，不分章节并写论文。
- 不让多人同时改同一权威报告/代码/论文，不把最终模型取舍和用户授权交给审查者；机械任务直接用现有脚本。
