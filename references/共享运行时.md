# 共享运行时与宿主能力

通用 Skill、命令行和 DSH `mm_*` 共用 `.math-modeling/` 项目状态。知识入口不绑定特定 Agent；状态、证据和校验由 `<SKILL_ROOT>/scripts/mathmodel.py` 处理。所有命令从题目目录执行，脚本使用绝对路径，参数遵守宿主 shell 的转义规则。

```powershell
python "<SKILL_ROOT>/scripts/mathmodel.py" init --project-root "<PROJECT_ROOT>" --options '{"scope":"full","profile":"balanced","paper_format":"word"}'
python "<SKILL_ROOT>/scripts/mathmodel.py" doctor --project-root "<PROJECT_ROOT>"
python "<SKILL_ROOT>/scripts/mathmodel.py" state --project-root "<PROJECT_ROOT>"
```

自动适配器可使用 `--request-base64` 传输 JSON 请求，避免将用户输入拼入 shell。具体字段以根目录 `RUNTIME_API.md`、CLI 帮助及 `mathmodel_runtime/resources/schemas/` 为准；不要猜测字段或自行改写状态文件。

用户交互见 [交互配置](交互配置.md)：通用 Agent 同样提供执行范围、材料、格式/profile、绘图、协作、环境与恢复选择，不需要 DSH 看板。已有偏好不重复询问；保存配置和启动执行是不同操作。

## 配置与本次执行

已有项目先 `state/context`，新项目才 `init`；`configure` 接收 `settings` 对象，省略项保持不变。五项 `graphics_tools` 与七项 `optional_collab` 采用布尔映射，显式 false 持久保留。`paper_requirements` 的非空 `text` 必须附 `source`。保存后读回配置，依赖检查只依据已保存值。

本次 `full/stage/task` 由 Agent 按用户指令执行，不是新增 CLI 动作，也不是 scope 的可选值。持久 scope 仍是 `full/modeling/programming/paper`。单项先用 `todo` 的 `operation:list,phase` 取真实任务，再调用 `phase` 验证前置条件；完成后只勾选真实完成的 `index` 并停止。阶段/单项不能通过修改 scope、重置清单或代作者签回执绕过门禁。需要时用 `log` 记录本次边界。

以下 Python 调用器使用真实 CLI 的 Base64 stdin，适合跨 shell 或较长的配置；替换两个绝对根目录后，按需调用示例，不把整段当必跑流水线。它只负责传参与读取结构化结果，不自动安装、执行模型或跳过失败。

```python
import base64
import json
import subprocess
import sys
from pathlib import Path

skill_root = Path("<SKILL_ROOT>")
project_root = Path("<PROJECT_ROOT>")

def mm(action, **options):
    request = dict(options, action=action, project_root=str(project_root))
    encoded = base64.b64encode(json.dumps(request, ensure_ascii=False).encode("utf-8"))
    process = subprocess.run(
        [sys.executable, str(skill_root / "scripts/mathmodel.py"), "--request-base64", "-"],
        input=encoded, capture_output=True, check=False,
    )
    result = json.loads(process.stdout.decode("utf-8"))
    if not result.get("ok"):
        raise RuntimeError(result)  # 保留 code/error，不把失败改写为成功
    return result

# 已有项目示例：仅保存用户明确选择的变化，不改 scope 或 profile。
mm("configure", settings={"graphics_tools": {"drawio": True, "scienceplots": False},
                          "optional_collab": {"terminology": True}})
context = mm("context")
tasks = mm("todo", operation="list", phase="programming")
# source_path 相对题目目录，filename 是保留的单个文件名。
# mm("input-import", kind="problem", filename="题面.md", source_path="incoming/题面.md")
# report = mm("environment")  # 生成报告与安装建议；不执行安装
```

`environment` 与 `doctor` 分开：前者返回实际解释器、required/selected/optional 分类及各项 ready/missing/error/manual 状态，后者提供能力概览。`ok:true` 不代表环境全就绪；`install_command` / `agent_prompt` 仅供用户选择后按既有授权处理，复制不等于执行。依赖变化后在同一解释器重新检测。

## 生命周期

1. `init` 创建项目；已有项目先 `state`，不要重新初始化丢失历史。
2. `doctor` 发现当前能力；`context/input-list` 盘点材料；配置与材料保存后用 `environment` 确认当前任务需要的依赖，只按授权准备相关缺口。
3. `phase` 进入当前阶段；`todo` 维护任务范围与阻塞。
4. `run` 记录真实命令、输入和代码哈希、参数、种子、输出与退出码；命令必须从项目目录可复现。
5. `artifact-add` 登记结果、图、代码、报告等，关联运行与所属问题；`claim-add` 将核心主张绑定证据位置。
6. `gate-prepare` 生成 task_id 和快照；独立审查后 `gate-record` 保存原回执。需要真实 reviewer_id 和文件哈希证据，不能虚构身份制造独立性。
7. `validate` 检查对应阶段产物和硬约束；声称整个已保存 scope 完成前用 `complete` 汇总。单项完成不代表全项目完成；产物变化后重新检查受影响部分。
8. `checkpoint-create` 保存版本，`checkpoint-list` 列出，`checkpoint-restore` 恢复；恢复前查看影响，保护用户新输入。

预览已登记产物用 `artifact-read` 的 `artifact_id` 或 `path`；真实日志用 `run-log-read` 的 `run_id`、`stream:stdout/stderr`，不把任意文件路径伪装为执行日志。恢复先请求 `checkpoint-restore`，不传 apply 即只返回 `changes` 和 `expected_revision`；有该恢复操作授权后，使用同一 checkpoint_id 加 `apply:true` 和返回的 expected_revision。预览后文件或状态变化需重新预览，不能强改版本继续。已明确授权无需重复求准，单纯预览请求则停在预览。

## 能力与审查等级

作者自检、宿主 Subagent、外部独立 Agent 与人工审查必须标明真实来源、身份、范围和输入快照。无 Subagent 时继续可验证计算，报告“产物已生成，独立验收未完成”，或接入真实外部审查；不能伪造 PASS。

`balanced`、`short`、`competition` 均不自动把历史图数/字数/页数变成官方要求；只有带规则来源的项目 rules 才增加硬约束。严格独立审查与能力限制由项目配置和回执明确表示。

缺网络、搜索源或格式引擎仅阻塞对应能力；记录 failed/empty/unavailable，保留已有可靠结果。替代工具需要满足用户需求并如实报告验证差异。

## 格式扩展

基础校验检查文件结构、非空内容、运行记录、哈希和证据引用，不替代视觉/科学审查。高级 DOCX、LaTeX、PDF、XLSX 工具另行准备依赖并核对各组件 LICENSE。未打包扩展时用 doctor 报告，不能根据一份 SKILL.md 推断脚本已安装。

内部证据持久化用于恢复和审计，不写入正式论文。建议数量只作提示，不用重复图或空内容满足配额。

LaTeX 交付需登记 `.tex` 入口，并用直接 TeX 工具的 paper run 关联代码和 PDF；运行记录保存实际 argv 与执行器路径。自定义包装脚本不自动获得编译来源信任。Word 的 max_pages 检查要求当前 DOCX 是渲染运行的输入，且对应 PDF 输出已登记；仅有一个短 PDF 不能证明 Word 页数合规。
