# 模型合同

> 共享运行时、当前 profile、用户要求和已核验规则优先；以下高级工具步骤仅在依赖/授权具备且任务需要时加载。缺能力时保留可验证产物并报告审查等级；图数和篇幅建议不阻断，每题最多两个独立模型体系仍按用户要求核验。
模型合同不是分析前的猜测，也不是独立交付物。它应在完整读题和检查附件后形成，并写入 `题目分析报告.md`。

## 内容

| 项目 | 必须回答的问题 |
|---|---|
| 任务定义 | 每个子问题要求计算、预测、评价或决策什么？ |
| 数据 | 输入字段、单位、范围、质量和只读文件是什么？ |
| 结论类型 | 理解题目后，最终需要给出哪类结论和指标？ |
| 模型 | 每题最终采用哪至多两个独立模型体系？列模型族编号、用途、同族近似/求解版本及计数依据；为何适配、第二个体系有何价值？ |
| 数学定义 | 变量、参数、目标函数、约束、假设和边界条件是什么？ |
| 实现 | 输入输出、算法步骤、停止条件和依赖是什么？ |
| 数据处理 | 缺失/类别/尺度/特征构造为何适合当前数据？哪些参数仅由训练数据拟合？如何保存并复用流程？ |
| 验证 | 泛化划分、敏感性、不确定性、数值与求解状态分别如何检查？不适用项依据是什么？ |
| 机理 | 单位量纲是否一致？初始/边界条件是否满足？如何比较步长或网格加密后的误差？ |
| 风险 | 哪些条件不满足时必须回退或更换方案？ |

数据判定标准必须注明题目、官方规则、文献或数据分析依据。
